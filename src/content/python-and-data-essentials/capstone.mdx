## The project: a weather brief

Use the free Open-Meteo services to make a short weather report for a city you choose. You may pick a different public API if you prefer, as long as it needs no payment and you respect its terms.

## Requirements

Build it as a script, `weather_brief.py`, in its own folder with its own virtual environment. It must:

1. **Look up** the city's coordinates with the geocoding API.
2. **Fetch** daily data for about two weeks: highest and lowest temperature and total precipitation.
3. **Handle failure**: a timeout, a status check, and a clear message if the city is not found.
4. **Load** the data into a pandas DataFrame with proper types, and save it to `data/weather.csv`.
5. **Summarize**: the warmest and coldest day, average temperatures, number of rainy days, and total rainfall.
6. **Chart**: save a PNG with temperatures over time, with labeled axes and a title that states the finding.
7. **Write a brief**: print or save a short text report in plain language.
8. Keep code in **small functions**, with no keys in the code (this API needs none, but design as if it did).

## A starting skeleton

```python
import requests
import pandas as pd

def find_city(name):
    """Return (latitude, longitude, display_name) for a city, or raise ValueError."""
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": name, "count": 1},
        timeout=10,
    )
    r.raise_for_status()
    results = r.json().get("results")
    if not results:
        raise ValueError(f"City not found: {name}")
    top = results[0]
    return top["latitude"], top["longitude"], f'{top["name"]}, {top.get("country", "")}'

def fetch_daily(lat, lon):
    """Return a DataFrame of daily weather for about two weeks."""
    r = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params={
            "latitude": lat,
            "longitude": lon,
            "daily": "temperature_2m_max,temperature_2m_min,precipitation_sum",
            "timezone": "auto",
            "past_days": 7,
            "forecast_days": 7,
        },
        timeout=10,
    )
    r.raise_for_status()
    daily = r.json()["daily"]
    df = pd.DataFrame(daily)
    df["time"] = pd.to_datetime(df["time"])
    return df

lat, lon, label = find_city("Berlin")
df = fetch_daily(lat, lon)
print(label)
print(df.head())
print(df.dtypes)
```

That covers steps 1 to 3 and the start of 4. The rest is yours: save the file, calculate the summary, chart it and write the brief. Run `df.describe()` and look at the numbers before you summarize them.

## Hints for the summary

- `df.loc[df["temperature_2m_max"].idxmax()]` gives the row of the warmest day.
- `(df["precipitation_sum"] > 0).sum()` counts days with rain.
- `df["temperature_2m_max"].mean()` gives an average.
- The first rows are past days and the later ones are forecasts. Say which in your brief.

## Check your work

- Does it run from a fresh terminal after `pip install -r requirements.txt`?
- Does it give a sensible message for a misspelled city?
- Do the numbers in the brief match the CSV when you check three of them by hand?
- Is the chart readable by someone who has not seen the code?
- Is the project in a Git repository with a `.gitignore` and at least three commits?

## A simple rubric

| Area | Strong | Needs work |
| --- | --- | --- |
| Correctness | Numbers match the data when you check them | Unchecked results |
| Robustness | Timeouts, status checks and clear errors | Crashes on bad input |
| Structure | Small named functions, readable code | One long script |
| Data handling | Correct types, missing values considered | Everything as text |
| Communication | Chart and brief state the finding plainly | Raw output only |
| Hygiene | Virtual environment, `.gitignore`, no secrets | Packages and keys everywhere |
