By the end of this lesson you can explain why a language model has no memory of its own, what "memory" really means in an agent, and which problems it is meant to solve.

## The model is stateless

A language model call is a pure function: tokens in, tokens out. Nothing from the last call survives unless you put it back into the next prompt. Everything we call "memory" in an agent is **code around the model** that decides what to store, and what to put back into the context window next time.

That gives you three constraints to design around:

1. **The context window is finite.** Even with very large windows, you pay for every token on every call, and latency grows with it.
2. **More context is not always better.** Irrelevant or contradictory text dilutes the signal. Selecting what goes in matters as much as fitting it.
3. **Sessions end.** Without storage, the agent greets a returning user as a stranger.

## What goes wrong without memory

- The user repeats their preferences every session.
- A long task loses its early decisions once the history is truncated.
- The agent repeats a mistake it made yesterday.
- Two agents working on one project cannot share what they learned.

## What goes wrong with *bad* memory

This is the part tutorials skip. A naive "store everything and retrieve the top matches" design causes its own failures:

- **Stale facts**: "I live in Austin" is still retrieved after the user moved.
- **Contradictions**: both versions get retrieved and the model picks one at random.
- **Noise**: trivia crowds out the three facts that matter.
- **Privacy leaks**: sensitive details are remembered, and surface in the wrong place.
- **Poisoning**: an attacker plants an instruction in a message and it is stored as a "fact".

<Callout title="The mindset for this course">
  Memory is a data engineering problem with a model in the loop. Treat it like
  any other store: decide what is written, how it is indexed, when it is
  updated or deleted, and how you measure whether retrieval was right.
</Callout>

## Context engineering is the umbrella

Memory is one piece of a larger discipline: curating the set of tokens the model sees on each step. Anthropic's engineering post frames this well, and covers techniques such as compaction and structured note-taking that we use later.
